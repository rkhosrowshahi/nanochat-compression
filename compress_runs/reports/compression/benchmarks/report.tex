\begin{abstract}
Two multi-objective evolutionary searches (NSGA-II) compress Qwen2.5-0.5B-Instruct. The first
(UBQ-ECSQ) trades calibration loss against encoded storage size, with global quantization and pruning
parameters; the second (hardware-aware) trades calibration loss against predicted GPU decode latency,
with a per-layer-group choice among bf16 and int4 kernel formats, MLP pruning and sublayer removal.
From each Pareto front, the solutions at calibration-loss increases of 0\%, 1\%, 2\%, 5\% and 10\% are
evaluated, with the uncompressed model, on eight standard benchmarks: six zero-shot commonsense and
reasoning tasks (PIQA, ARC-Easy, ARC-Challenge, HellaSwag, WinoGrande, BoolQ), 5-shot MMLU and 5-shot
GSM8K. UBQ-ECSQ: at 8.0 bits per weight the model is $2.00\times$ smaller with no loss of accuracy; at
6.0--6.7 bits per weight ($2.39$--$2.66\times$ smaller) it keeps 98\% of the average accuracy; at 5.0
bits per weight ($3.2\times$ smaller) it keeps 88\%. Hardware-aware: $1.56\times$ faster decoding
keeps 98.8\% of the accuracy, and $1.98\times$ faster decoding with $3.4\times$ less memory (4.5 bits
per weight, almost all int4) keeps 95.1\%; removing sublayers costs far more accuracy than it saves
time.
\end{abstract}

\section{UBQ-ECSQ compression scheme}

All 169 weight matrices of the model are compressed, including the token embedding, which is tied to
the output head (494.0M weights, 100\% of the parameters). Every matrix uses the same five parameters
(genes). For a weight $w$ in output row $r$, with $\sigma_r$ and $m_r=\max|w_r|$ taken from the
original weights:
\begin{enumerate}[label=\arabic*.]
  \item \textbf{Pruning:} $w\to0$ if $\alpha\,\sigma_r \le w \le \beta\,\sigma_r$, with $\alpha\le0\le\beta$.
  \item \textbf{Uniform quantization (UBQ):} a symmetric, zero-preserving grid of $k$ levels with step
        $s_r = c\,m_r / \lfloor (k-1)/2 \rfloor$, clipping factor $c\in[0.7,1]$; pruned weights stay 0.
  \item \textbf{Entropy-constrained merge (ECSQ):} each non-empty level gets a model-wide centroid;
        contiguous levels are merged by dynamic programming to minimize $D+\lambda R$ (added squared
        error plus entropy of level occupancy), keeping a fraction $\rho$ of the levels. The zero level
        is never merged. $\rho=1$ means no merge.
\end{enumerate}
Encoded size is the smaller of a dense code ($\lceil\log_2 k_\text{used}\rceil$ bits per weight) and a
bitmap code (1 bit per weight plus a code per non-zero), plus a 16-bit scale per row and a lookup table
per matrix. Sizes are in MB ($10^6$ bytes); bits per weight include scales and tables.

\section{UBQ-ECSQ search}

\begin{itemize}
  \item \textbf{Objectives (minimized):} $\dloss$, the next-token cross-entropy on the calibration set
        minus that of the uncompressed model, and the encoded size.
  \item \textbf{Constraint:} $\dloss \le 1.0$ nats.
  \item \textbf{Calibration set:} 8 sequences of 2048 tokens from C4 (train, English), fixed for the
        whole run. Uncompressed loss $\mathcal{L}_0 = 2.8854$ nats.
  \item \textbf{Genes:} $\log_2 k$ with $k\in[16,256]$ (range set by a warm-up on the model's
        error-vs-$k$ curve), $c\in[0.7,1]$, $\alpha\in[-1,0]$, $\beta\in[0,1]$, $\rho\in[0,1]$.
  \item \textbf{NSGA-II:} population 100, 50 generations, seed 42.
\end{itemize}

\section{Benchmark protocol}

All models are evaluated with the same harness (lm-evaluation-harness 0.4.13), in bf16, on full
evaluation splits, without a chat template, with fixed seeds. Compressed weights are reconstructed in
place, so the models differ only in their weight values. The hardware-aware models were evaluated on a
second machine together with their own uncompressed reference, which agrees with the first within one
standard error on every task; each model is compared with the reference from its own machine.

\paragraph{Observations.}
\begin{itemize}
  \item \textbf{8 bits per weight is lossless.} Q0 is $2.00\times$ smaller and every benchmark is
        within 0.7 points of the uncompressed model, inside the standard errors (100.6\% kept).
  \item \textbf{1--2\% calibration error keeps 98\% of the accuracy.} Q1 and Q2 are $2.39\times$ and
        $2.66\times$ smaller. The commonsense tasks and MMLU stay within 2 points; GSM8K drops 3.6--4.5
        points and BoolQ up to 3.5.
  \item \textbf{At 5.0 bits per weight, about 12\% of the average accuracy is lost.} Q5 and Q10 are
        $3.2\times$ smaller and keep 88\%. The commonsense tasks lose at most 5 points; BoolQ breaks
        (Q5: 49.7\%, below the 62.2\% of always answering ``yes'').
  \item \textbf{GSM8K is the most sensitive benchmark:} 31.2\% uncompressed, 27--28\% at 1--2\%
        error, 10--13\% at 5--10\% error.
  \item \textbf{Calibration loss does not rank the models downstream.} Q5 has half the calibration
        error of Q10 and lower test perplexity, and is better on MMLU (45.0 against 38.3), but worse on
        BoolQ and GSM8K; the two averages are equal. Below about 6 bits per weight, models need a
        benchmark check before use.
\end{itemize}

\section{Hardware-aware compression}

\subsection{Scheme and search}

The compressed model is the deployed model: every choice maps onto a kernel that runs on the GPU, and
the cost is the decode latency and memory of that model, not a storage size.
\begin{itemize}
  \item \textbf{Formats:} bf16, or int4 with an asymmetric bf16 scale and zero per group of 32, 64 or
        128 input weights (g32, g64, g128), on PyTorch's int4 matrix-multiplication kernel. The
        clipping of each int4 group minimizes the activation-weighted error and is solved per group,
        not searched.
  \item \textbf{Genes (23):} the format of each of four roles (attention q/k/v, attention output, MLP
        up/gate, MLP down) in each of four depth bands of 6 layers (16 genes); the format of the output
        head, tied to the token embedding (1); the fraction of MLP neurons kept per band, from
        $\{1, 0.875, 0.75, 0.625, 0.5\}$, by activation-weighted importance (4); the number of attention
        and of MLP sublayers removed, 0--6 each, in a fixed order ranked by the loss increase of removing
        each sublayer alone (2).
  \item \textbf{Objectives (minimized):} $\dloss$ on the same calibration set as above
        ($\mathcal{L}_0 = 2.8854$ nats), and the decode latency of one token (batch 1, 1024 tokens of
        context), predicted from per-kernel times measured on an RTX 3060 GPU. Memory (weights plus the
        KV cache of 1024 tokens; 1001\,MB uncompressed) is reported, not optimized.
  \item \textbf{Constraint:} $\dloss \le 1.0$ nats. \textbf{NSGA-II:} population 40, 12 generations,
        seed 42.
\end{itemize}

\subsection{Pareto fronts}

The final front has 40 solutions from 2.85 to 6.78\,ms and 239 to 1001\,MB (Figure~\ref{fig:hwfront}).
With formats alone, $\dloss$ stays at or below 0.18 nats (6\%) down to 3.36\,ms, the model with every
matrix in int4 g128; every faster solution prunes MLP neurons or removes sublayers, and $\dloss$ rises
to 0.20--0.81 nats. Five solutions spread along the front and the uncompressed model were scored on 32
windows each of WikiText-2 test and C4 validation (Figure~\ref{fig:hwtest}).

\FloatBarrier
\paragraph{Observations.}
\begin{itemize}
  \item \textbf{The 0\% level brings no speed-up.} H0 changes one band of one role to int4 (1\% of the
        weights) and is 1.01$\times$ faster; any larger change costs measurable calibration loss.
  \item \textbf{1--2\% calibration error: up to 1.56$\times$ faster at 98.8\% accuracy.} H1 and H2 stay
        within 1.6 points on every benchmark except GSM8K ($-2.4$ and $-1.8$).
  \item \textbf{Almost-all-int4 is the efficient point.} H5 is 1.98$\times$ faster with 3.43$\times$ less
        memory and keeps 95.1\%: the commonsense tasks and MMLU lose at most 2.9 points, GSM8K 9.8.
  \item \textbf{Removing sublayers does not pay.} H10 removes one attention and one MLP sublayer for
        0.15\,ms (4\%) over H5 and loses another 5.5 points of average accuracy (84.6\% kept); GSM8K
        falls to 4.9\%, ARC-Easy and MMLU by 9.5 and 9.4 points.
  \item \textbf{Calibration loss ranks these models correctly:} accuracy falls monotonically with the
        level, unlike the UBQ-ECSQ models at 5--10\%.
  \item \textbf{Against UBQ-ECSQ:} H5 at 4.5 bits per weight keeps 95.1\%, the UBQ-ECSQ models at
        5.0 bits per weight 88\% (BoolQ 66.5 against 49.7, GSM8K 20.5 against 9.7). The UBQ-ECSQ sizes
        are entropy-coded storage that must be decoded before use; the hardware-aware models run
        directly on int4 kernels.
\end{itemize}
